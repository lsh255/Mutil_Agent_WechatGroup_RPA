# 架构设计文档 v3

## 1. 架构概述

### 1.1 设计理念

本项目采用 **Orchestrator-Worker（协调器-工作器）** 架构模式，基于 **LangGraph** 构建有状态的多智能体工作流系统。系统通过 **Redis Streams** 实现异步消息传递，通过 **ChromaDB** 实现知识库存储与RAG检索。

### 1.2 核心设计原则

| 原则 | 说明 |
|------|------|
| 状态驱动 | LangGraph状态机驱动工作流流转 |
| 异步解耦 | Redis Streams实现服务间解耦通信 |
| 智能编排 | 多Agent协同处理复杂业务场景 |
| 容错设计 | 检查点机制支持工作流恢复 |

## 2. 核心架构模块

### 2.1 LangGraph工作流编排层

#### 2.1.1 工作流定义

工作流采用 **StateGraph** 构建，定义了四个核心节点和条件分支：

```python
def create_workflow():
    workflow = StateGraph(AgentState)
    
    # 添加节点
    workflow.add_node("monitor", monitor_node.process)
    workflow.add_node("multimodal", multimodal_node.analyze)
    workflow.add_node("state_tracker", state_tracker_node.update)
    workflow.add_node("document", document_node.execute)
    
    # 设置入口
    workflow.set_entry_point("monitor")
    
    # 添加边
    workflow.add_edge("monitor", "multimodal")
    workflow.add_edge("multimodal", "state_tracker")
    
    # 条件分支
    workflow.add_conditional_edges(
        "state_tracker",
        state_tracker_node.should_generate_document,
        {"yes": "document", "no": END}
    )
    
    return workflow.compile()
```

#### 2.1.2 工作流节点职责

| 节点 | 职责 | 输入 | 输出 |
|------|------|------|------|
| **MonitorNode** | 接收原始消息，载入工作流状态 | RawMessage | System消息日志 |
| **MultimodalNode** | 多模态分析，调用AI模型识别任务类型 | RawMessage | MultimodalAnalysis |
| **StateTrackerNode** | 更新任务状态，判断工作流走向 | MultimodalAnalysis | TaskStatus + 路由决策 |
| **DocumentNode** | 执行文档更新操作 | DocumentUpdate | 执行结果 |

#### 2.1.3 状态定义 (AgentState)

```python
class AgentState(TypedDict):
    raw_message: Optional[RawMessage]           # 原始消息
    multimodal_analysis: Optional[MultimodalAnalysis]  # 多模态分析结果
    task_status: Optional[TaskStatus]           # 任务状态
    document_updates: List[DocumentUpdate]      # 文档更新指令
    messages: Annotated[list, add_messages]     # 消息记录
    context: Dict[str, Any]                     # 上下文信息
```

#### 2.3.3 变化检测机制

```python
# dHash (Difference Hash) 变化检测
def detect_changes(self, screenshot):
    # 计算dHash值
    current_hash = self.calculate_dhash(screenshot)
    
    # 与上一次截图比较
    if self.last_hash:
        hamming_distance = self.calculate_hamming_distance(
            current_hash, self.last_hash
        )
        
        # 阈值判断 (默认为5)
        if hamming_distance > self.threshold:
            self.last_hash = current_hash
            return True
    
    self.last_hash = current_hash
    return False
```

#### 2.3.4 消息分类逻辑

```python
class MessageClassifier:
    """消息分类器"""
    
    def classify(self, raw_message: RawMessage) -> MessageType:
        """
        分类消息类型
        
        Returns:
            MessageType.TEXT: 纯文本消息
            MessageType.IMAGE: 纯图片消息
            MessageType.MIXED: 图文混合消息
        """
        has_text = bool(raw_message.content)
        has_image = bool(raw_message.image_path)
        
        if has_text and has_image:
            return MessageType.MIXED
        elif has_image:
            return MessageType.IMAGE
        else:
            return MessageType.TEXT
```

#### 2.4.2 RAG检索流程

```python
# 多模态分析节点中的RAG检索
def retrieve_knowledge(self, query: str) -> List[Document]:
    """
    使用RAG检索相关知识
    
    Args:
        query: 查询文本
        
    Returns:
        相关文档列表
    """
    # 1. 将查询文本向量化
    embedding = self.embedding_model.embed_query(query)
    
    # 2. 在ChromaDB中检索
    results = self.vector_store.similarity_search_by_vector(
        embedding=embedding,
        k=3  # 返回最相关的3个文档
    )
    
    return results
```

```
└────┬────┘
     │ 接到任务消息
     ↓
┌─────────┐
│ DURING  │ ← 任务进行中
└────┬────┘
     │ 完成任务消息

```

```python
    for attempt in range(max_retries):
        try:
            message = consumer.read_messages(
                stream_name=queue_name,
                consumer_group="orchestrator",
                consumer_name="consumer_001"
            )
            return message
        except Exception as e:
            if attempt == max_retries - 1:
                raise
            time.sleep(2 ** attempt)  # 指数退避
```

## 13. 总结

本架构设计文档v3基于项目实际代码逻辑，采用 **Orchestrator-Worker** 架构模式，通过 **LangGraph** 实现工作流编排，通过 **Redis Streams** 实现异步消息传递，通过 **ChromaDB** 实现知识库存储与RAG检索。

核心特点：
1. **状态驱动**: LangGraph状态机驱动工作流流转
2. **异步解耦**: Redis Streams实现服务间解耦通信
3. **智能编排**: 多Agent协同处理复杂业务场景
4. **容错设计**: 检查点机制支持工作流恢复
5. **可扩展性**: 插件化Agent和动态工作流节点

未来优化方向：
